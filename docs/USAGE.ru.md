# unattend-gen — руководство пользователя

[English](USAGE.md) | Русский | [简体中文](USAGE.zh-CN.md) | [Español](USAGE.es.md) | [हिन्दी](USAGE.hi.md)

Это полный справочник по `unattend-gen`: CLI/TUI-инструменту на Go, который
генерирует файлы ответов `autounattend.xml` для Windows 10/11. Вы один раз
создаёте **профиль** (JSON-файл с описанием того, как установить и настроить
Windows), а затем генерируете из него файл ответов при каждой переустановке.
Веб-форма и доступ к сети не нужны, инструмент поставляется одним
статическим бинарником.

Краткий обзор возможностей — в [README.ru.md](../README.ru.md). Это
руководство описывает каждую команду, каждый экран TUI и каждое поле профиля.

Если это руководство и сгенерированный XML расходятся, правильным считается
код. Руководство написано вручную по тому же источнику истины, который
использует сам инструмент (`internal/profile/schema.go`), но ошибки возможны.
Если нашли ошибку, создайте issue.

## Что делает инструмент и чего намеренно не делает

`unattend-gen` строит один файл `autounattend.xml`. Вы кладёте его на
USB-флешку (или в корень установочного носителя) рядом с установщиком
Windows, и Windows Setup запускает его автоматически, пропуская все вопросы,
которые вы настроили заранее.

**Диск не размечается и не форматируется.** Windows Setup всегда
интерактивно спрашивает, куда устанавливать систему. Это сделано намеренно,
а не потому, что функция не дописана. Инструмент отвечает за всё, что идёт
*после* того, как вы выбрали диск или раздел: язык, аккаунты, твики, удаление
приложений, персонализация и так далее.

**Для работы не нужен доступ к сети.** Веб-формы и сервера нет: это
локальный бинарник, который читает JSON-профиль и пишет XML-файл.

## Установка и сборка

Для сборки из исходников нужен Go 1.23+ (готовые бинарники в этом
руководстве не публикуются; проверьте страницу Releases репозитория, есть ли
сборка под вашу платформу).

```sh
git clone https://github.com/FlexEbat/unattend-gen.git
cd unattend-gen
go build -o unattend-gen ./cmd/unattend-gen
```

Получится один статический бинарник `unattend-gen` (или `unattend-gen.exe` в
Windows) без зависимостей времени выполнения.

## Быстрый старт

Самый быстрый путь — интерактивный TUI:

```sh
./unattend-gen tui
```

Пройдите по экранам (переключайтесь клавишами **Ctrl+N**/**Esc**, к итоговому
экрану можно перейти сразу по **Ctrl+R**), затем сохраните. Получится
JSON-профиль, из которого можно генерировать файл позже или править его
вручную.

Если удобнее работать с JSON напрямую:

```sh
# Новый профиль со значениями по умолчанию (в основном «спросить при установке»)
./unattend-gen profile init my-pc

# ...правьте my-pc.json вручную или продолжайте в TUI:
./unattend-gen tui my-pc.json

# Проверить, что профиль корректен
./unattend-gen validate my-pc.json

# Сгенерировать файл ответов (по умолчанию пишет autounattend.xml
# рядом с профилем)
./unattend-gen generate my-pc.json
```

Скопируйте получившийся `autounattend.xml` в корень установочной USB-флешки с
Windows (рядом с `setup.exe`, либо в корень ISO, если собираете свой носитель)
и загрузитесь с неё: Windows Setup найдёт и применит файл автоматически.

## Справочник по CLI

Каждая команда сначала проверяет входные данные и завершается с ошибкой
(ненулевой код возврата, текст ошибки в stderr), а не генерирует неполный или
угаданный файл.

### `profile init <name> [--preset minimal|single-user]`

Создаёт `<name>.json` в текущей папке. Без `--preset` профиль строится из
встроенных значений по умолчанию (язык/локаль/раскладка `en-US`, всё
остальное близко к «спросить при установке»; см. [значения по
умолчанию](#значения-по-умолчанию) ниже). С `--preset` берётся один из двух
встроенных пресетов (см. [Встроенные пресеты](#встроенные-пресеты)), при этом
`name` всегда равен тому, что вы передали в командной строке, независимо от
содержимого пресета.

```sh
./unattend-gen profile init laptop --preset single-user
# -> laptop.json
```

### `profile list`

Выводит каждый файл `*.json` из `./profiles` (по одному пути на строку и
ничего больше, вывод рассчитан на использование в скриптах). Папка должна
существовать и содержать профили; других настроек расположения профилей нет.

```sh
./unattend-gen profile list
```

### `validate <profile.json>`

Выполняет ту же проверку, что и `generate`, но не строит файл ответов.
Печатает по одной ошибке на строку в stderr и завершается с ненулевым кодом,
если что-то не так; если профиль корректен, печатает `профиль корректен`
(сообщения валидации и эта строка успеха выводятся по-русски, см. [Языковое
соглашение](#языковое-соглашение) ниже) и завершается с кодом 0.

```sh
./unattend-gen validate laptop.json
```

### `generate <profile.json> [-o path]`

Проверяет профиль, затем строит и записывает файл ответов. Без
`-o`/`--output` файл записывается как `autounattend.xml` в ту же папку, где
лежит профиль. При успехе печатает путь к записанному файлу.

```sh
./unattend-gen generate laptop.json
./unattend-gen generate laptop.json -o /media/usb/autounattend.xml
```

### `tui [profile.json]`

Открывает интерактивный терминальный интерфейс. Без аргумента стартует со
значений по умолчанию. Если указан путь к профилю, сначала загружает его тем
же загрузчиком, что использует `validate`/`generate`, так что можно ходить
по кругу: править в TUI, сохранять, дорабатывать JSON вручную, снова
открывать в TUI и так далее.

```sh
./unattend-gen tui
./unattend-gen tui laptop.json
```

<a id="языковое-соглашение"></a>
**О языке интерфейса**: код, комментарии, сообщения коммитов и обычный
консольный текст (справка по командам, сообщения об успехе и ошибке при
выводе в конвейер) — на английском. Текст, который TUI показывает при
заполнении профиля, и все сообщения валидации — на русском. Это соглашение
проекта, а не ошибка.

## TUI по экранам

Экраны идут в таком порядке; **Ctrl+N** переходит к следующему, **Esc**
возвращает назад, **Ctrl+R** переходит сразу к Review из любого места,
**Tab** / **Shift+Tab** переключают поля на экране, **Пробел** переключает
флажки. Каждый экран синхронизирует один и тот же профиль в памяти, поэтому
при переходах вперёд и назад ничего не теряется.

1. **Welcome** — приветственный экран, настраивать нечего.
2. **Language** — язык интерфейса / локаль / раскладка клавиатуры (коды
   BCP-47), режим редакции Windows (интерактивно / универсальный ключ /
   свой ключ / ключ в прошивке BIOS-UEFI), отдельный ключ только для
   активации и архитектура процессора.
3. **Accounts** — имя компьютера (или пусто, чтобы Windows сгенерировала
   его), часовой пояс, до 5 локальных аккаунтов (имя/отображаемое имя/
   пароль/группа) в редактируемой таблице, поведение первого входа и флажок
   «не требовать учётную запись Microsoft» (best-effort).
4. **Tweaks** — экспресс-настройки (телеметрия/диагностика), все 33
   системных твика (см. [полный список](#системные-твики) ниже), политика
   срока действия паролей и блокировки аккаунтов, твики проводника. Всё на
   одном экране, потому что все это настройки вида «переключить значение по
   умолчанию».
5. **Wifi** — сеть Wi-Fi для автоподключения при первой загрузке: либо
   заполнить SSID/тип защиты/пароль/скрытую сеть, либо вставить сырой XML
   экспортированного профиля WLAN.
6. **Apps** — три группы флажков: приложения для удаления (пакеты Appx),
   компоненты Windows для удаления (возможности DISM) и устаревшие
   необязательные компоненты (третий, отдельный механизм удаления); см.
   [полные списки](#удаление-приложений-и-компонентов) ниже.
7. **Personalization** — светлая/тёмная тема (для системы и приложений
   отдельно), акцентный цвет, где он отображается («Пуск»/панель задач,
   заголовки окон), прозрачность и однотонный цвет рабочего стола.
8. **Accessibility** — залипание клавиш (выкл/отключено/своя комбинация
   флагов) и начальное состояние Caps/Num/Scroll Lock, а также реагирует ли
   система на их нажатие.
9. **Desktop** — какие значки показывать на рабочем столе (Этот компьютер,
   Корзина и т. д., всего 13) и какие специальные папки закрепить в меню
   «Пуск» рядом с кнопкой питания (Windows 11).
10. **VisualEffects** — «Параметры быстродействия» Windows: пресет (лучший
    вид / лучшая производительность) или 17 отдельных переключателей
    анимации и оформления.
11. **Taskbar** — меню «Пуск» и панель задач: отключение виджетов,
    выравнивание панели задач по левому краю (Windows 11), скрытие кнопки
    «Представление задач», отключение результатов Bing в поиске, показ всех
    значков в области уведомлений, режим поля поиска, закрепления «Пуска»
    (JSON для Windows 11) / плитки (XML для Windows 10) и закреплённые
    значки панели задач (пусто или свой XML раскладки).
12. **Advanced** — установка гостевых инструментов виртуальных машин
    (VirtualBox/VMware/VirtIO/Parallels), сырой XML политики AppLocker,
    PowerShell-скрипт для вычисления имени компьютера и три небольших
    флажка: оставить файл ответов после установки вместо удаления, запускать
    экранный диктор и скрывать пароли аккаунтов в сгенерированном XML.
13. **Scripts** — по одному пользовательскому скрипту на категорию
    (System/DefaultUser/FirstLogon/UserOnce, см. [Пользовательские
    скрипты](#пользовательские-скрипты) ниже) в многострочном поле, плюс
    флажок перезапуска проводника после выполнения скриптов.
14. **Review** — обновляемая на лету сводка всего профиля и, если он
    проходит проверку, предпросмотр сгенерированного XML.

Не каждое поле каждого экрана один к одному соответствует ключу верхнего
уровня JSON: несколько экранов редактируют вложенные объекты (например,
`system_tweaks`, `personalization`). [Справочник по JSON
профиля](#справочник-по-json-профиля) ниже организован по структуре JSON с
пометкой, какой экран редактирует каждую часть, так что поле можно найти в
любом направлении.

## Справочник по JSON профиля

Профиль — это один JSON-объект с `schema_version: 1`. Каждое поле ниже
необязательно, если не отмечено как **обязательное**; пропуск необязательного
поля (или значение `null`, или булево `false`) означает «не трогать
поведение Windows по умолчанию», за одним намеренным исключением, которое
отмечено в своём месте.

### Верхний уровень

| Поле | Тип | Примечания |
|---|---|---|
| `schema_version` | int | **Обязательное**, должно быть `1`. |
| `name` | string | **Обязательное**. Произвольный текст: в XML не попадает, это просто метка самого файла профиля. |

### Язык и редакция — *(экран Language)*

```json
"language": {
  "ui_language": "en-US",
  "locale": "en-US",
  "keyboard_layout": "en-US"
}
```

Все три поля **обязательны** и содержат коды BCP-47 (например, `en-US`,
`de-DE`, `ru-RU`). `keyboard_layout` соответствует языку ввода; `locale`
задаёт и системную локаль, и пользовательскую.

```json
"edition": {
  "mode": "interactive",
  "edition": null,
  "product_key": null
}
```

- `mode`, одно из:
  - `"interactive"` — Windows Setup спрашивает редакцию и ключ во время
    установки.
  - `"generic_key"` — требует, чтобы `edition` было одним из `"Home"`,
    `"Pro"`, `"Education"`, `"Enterprise"`; Setup использует публичный
    универсальный ключ Microsoft (ключ установки клиента KMS) для этой
    редакции, активировать систему придётся позже.
  - `"custom_key"` — требует `product_key`, настоящий 25-символьный ключ в
    виде `XXXXX-XXXXX-XXXXX-XXXXX-XXXXX`. Этот же ключ используется для
    активации, если явно не задан `activation_key` (см. ниже).
  - `"firmware"` — использует ключ продукта, уже записанный в прошивке
    BIOS/UEFI устройства (типично для предустановленной OEM-версии Windows);
    ключ не запрашивается и не записывается.

```json
"activation_key": null,
"processor_architecture": ""
```

- `activation_key`: отдельный ключ, используемый **только** для активации
  (`Microsoft-Windows-Shell-Setup/ProductKey`), независимо от того, какой
  ключ (если есть) использует `edition` для выбора устанавливаемой
  редакции. Оставьте `null`, чтобы использовать `edition.product_key` (только
  если `edition.mode` равен `"custom_key"`) или не активировать систему
  вообще.
- `processor_architecture`: одно из `"amd64"` (по умолчанию при пустом или
  отсутствующем значении), `"x86"`, `"arm64"`. На профиль поддерживается
  только одна архитектура: в отличие от некоторых других генераторов, этот
  инструмент не строит один файл ответов для установки на несколько
  архитектур.

### Имя компьютера и часовой пояс — *(экран Accounts)*

```json
"computer_name": null,
"computer_name_script": null,
"timezone": null
```

- `computer_name`: статическое имя хоста (1–15 символов, буквы/цифры/дефисы,
  не может начинаться или заканчиваться дефисом и состоять только из цифр).
  `null` позволяет Windows сгенерировать случайное имя.
- `computer_name_script`: PowerShell-скрипт, выполняемый при установке;
  его вывод становится именем компьютера. Подходит для динамических имён
  (например, по серийному номеру или схеме именования). **Взаимоисключает**
  `computer_name`: если заданы оба, это ошибка валидации. Переименование
  выполняется фоновым процессом, который какое-то время после установки
  повторно применяет имя, обходя перезапись имени самой Windows на проходе
  specialize.
- `timezone`: идентификатор часового пояса Windows, например `"Russian
  Standard Time"`, `"Pacific Standard Time"`, `"UTC"`. `null` позволяет
  Windows определить пояс автоматически. Инструмент не проверяет, что строка
  обозначает существующий часовой пояс (список большой и зависит от версии),
  а проверяет только, что значение не пустая строка, если оно задано.

### Аккаунты и первый вход — *(экран Accounts)*

```json
"accounts": [
  {
    "name": "alice",
    "display_name": null,
    "password": "Sup3rSecret!",
    "group": "Administrators"
  }
],
"first_logon": { "mode": "first_created_account" }
```

- `accounts`: до 5 записей.
  - `name` — **обязательное**, ≤20 символов, без `" / \ [ ] : ; | = , + * ? < >`.
  - `display_name` — необязательное отображаемое имя.
  - `password` — `null` означает отсутствие пароля; пустая строка
    недопустима (используйте `null`).
  - `group` — **обязательное**, `"Administrators"` или `"Users"`.
- `first_logon.mode`, одно из:
  - `"none"` — без автовхода; при первой загрузке показывается обычный
    экран входа.
  - `"first_created_account"` — автовход в первый аккаунт из `accounts`
    (список не должен быть пустым).
  - `"builtin_administrator"` — автовход в скрытую встроенную учётную запись
    Administrator; требует заданного
    `first_logon.builtin_administrator_password`.

### Экспресс-настройки и обходы

```json
"express_settings": { "mode": "interactive" },
"bypass_online_account_requirement": false
```

- `express_settings.mode`: `"interactive"` (Setup спрашивает про телеметрию и
  прочее), `"all_enabled"` или `"all_disabled"`. Любое значение, кроме
  `"interactive"`, также автоматически скрывает несколько экранов OOBE
  (EULA, регистрация OEM, настройка сети).
- `bypass_online_account_requirement`: попытка (best-effort) позволить Setup
  завершиться с локальной учётной записью вместо входа в аккаунт Microsoft
  (записывает известное значение реестра `BypassNRO`). **Не гарантируется**:
  Microsoft не раз закрывала этот обход в 2025–2026 годах, поэтому не
  рассчитывайте на него для парка машин, не проверив на вашей сборке Windows.
  Локальные аккаунты и так надёжно пропускают этот запрос, если в `accounts`
  есть хотя бы одна запись, независимо от этого флага.

<a id="системные-твики"></a>
### Системные твики — *(экран Tweaks)*

Все 33 поля внутри `"system_tweaks": { ... }` — обычные булевы значения,
по умолчанию `false` (без изменений), **кроме** `keep_sensitive_files`,
который описан ниже:

| Поле | Что делает |
|---|---|
| `disable_windows_update` | Приостанавливает/отключает Windows Update. |
| `disable_uac` | Отключает запросы контроля учётных записей (UAC). |
| `bypass_win11_requirements` | Пропускает проверки TPM/Secure Boot/ОЗУ (windowsPE, до того как Setup их оценивает). |
| `disable_smart_app_control` | Отключает Smart App Control. |
| `disable_smart_screen` | Отключает SmartScreen (система и Edge). |
| `disable_fast_startup` | Отключает быстрый запуск (гибридную загрузку). |
| `disable_system_restore` | Отключает восстановление системы. |
| `enable_long_paths` | Включает поддержку длинных путей NTFS длиннее 260 символов. |
| `enable_remote_desktop` | Включает удалённый рабочий стол и правило брандмауэра. |
| `allow_powershell_scripts` | Устанавливает политику выполнения PowerShell в `RemoteSigned`. |
| `disable_last_access_timestamp` | `fsutil behavior set disablelastaccess 1`. |
| `prevent_device_encryption` | Предотвращает автоматическое шифрование устройства BitLocker. |
| `disable_auto_sign_on_last_user` | Отключает автоматический вход последнего интерактивного пользователя после перезапуска. |
| `disable_wpbt` | Отключает выполнение Windows Platform Binary Table. |
| `audit_process_creation` | Включает аудит создания процессов, включая командную строку. |
| `hide_edge_first_run` | Пропускает первый запуск Edge. |
| `disable_edge_startup_boost` | Отключает ускоренный запуск Edge и фоновый режим. |
| `delete_hidden_junctions` | Удаляет устаревшие junction-точки NTFS (например, `C:\Documents and Settings`) — для аккаунта установки и всех будущих аккаунтов. |
| `prevent_automatic_reboot` | Не даёт Windows Update перезагружать машину, которую используют (регистрирует запланированную задачу, постоянно сдвигающую «активные часы» к текущему времени). |
| `turn_off_system_sounds` | Устанавливает звуковую схему «Без звука» — для аккаунта установки и всех будущих аккаунтов. |
| `disable_app_suggestions` | Отключает тихую установку рекомендуемых приложений через Content Delivery Manager. |
| `disable_pointer_precision` | Отключает «Повышенную точность установки указателя» (ускорение мыши). |
| `prevent_device_apps` | Не даёт Windows скачивать и устанавливать приложения, связанные с конкретным оборудованием. |
| `harden_system_drive_acl` | Убирает у группы «Прошедшие проверку» право записи в `C:\`. |
| `make_edge_uninstallable` | Переключает внутренний флаг политики, позволяющий показывать у Edge пункт «Удалить». |
| `delete_windows_old` | Удаляет `C:\Windows.old` (актуально только при обновлении на месте; при чистой установке безвредная пустая операция). |
| `disable_core_isolation` | Отключает целостность памяти / защиту на основе виртуализации (полезно в некоторых гостевых ВМ или со старыми драйверами). |
| `delete_edge_desktop_icon` | Удаляет ярлык Microsoft Edge с рабочего стола — для аккаунта установки и всех будущих аккаунтов. |
| `disable_widgets` | Отключает панель «Виджеты». |
| `left_taskbar` | Выравнивает панель задач по левому краю (Windows 11; по умолчанию по центру). |
| `hide_task_view_button` | Скрывает кнопку «Представление задач» на панели задач. |
| `disable_bing_results` | Отключает веб-результаты Bing в поиске на панели задач. |
| `show_all_tray_icons` | Всегда показывает все значки области уведомлений, а не сворачивает неактивные (механизмы в Windows 10 и 11 различаются, это обрабатывается автоматически). |

`keep_sensitive_files` находится на верхнем уровне профиля, а не внутри
`system_tweaks`; см. примечание ниже, потому что его поведение по умолчанию —
единственное намеренное исключение из правила «false/отсутствие означает без
изменений» во всей схеме.

```json
"keep_sensitive_files": false
```

По умолчанию (`false`, то есть и **при отсутствии в JSON**) инструмент после
завершения установки удаляет `C:\Windows\Panther\unattend.xml` /
`unattend-original.xml` (копии вашего файла ответов, которые хранит Windows
Setup, вместе с паролями открытым текстом, если вы не включили
`obscure_passwords`) и собственный временный файл профиля Wi-Fi. Установите
`true`, чтобы оставить эти файлы на месте. Это единственное поле во всей
схеме, где значение по умолчанию *что-то делает*, а не *ничего не меняет*:
пароли открытым текстом на диске после установки хуже, чем нарушение обычного
соглашения.

### Срок действия паролей и блокировка аккаунтов — *(экран Tweaks)*

```json
"password_expiration": { "mode": "default", "days": null },
"account_lockout": {
  "mode": "default",
  "threshold": null,
  "window_minutes": null,
  "duration_minutes": null
}
```

- `password_expiration.mode`: `"default"` (значение Windows по умолчанию,
  42 дня; команда не выдаётся), `"never"` (пароли не истекают) или
  `"custom"` (требует `days` ≥ 1).
- `account_lockout.mode`: `"default"` (значение Windows по умолчанию:
  10 неудачных попыток / окно 10 минут / блокировка на 10 минут),
  `"disabled"` (блокировка отключена) или `"custom"` (требует все три
  числовых поля, каждое ≥ 1).

### Твики проводника — *(экран Tweaks)*

```json
"file_explorer": {
  "hidden_files": "default",
  "show_file_extensions": false,
  "classic_context_menu": false,
  "hide_folder_tooltips": false,
  "open_to_this_pc": false,
  "show_end_task_in_taskbar": false
}
```

- `hidden_files`: `"default"`, `"show_hidden"` (показывать скрытые файлы) или
  `"show_all"` (показывать скрытые и защищённые системные файлы).
- Остальные булевы значения: показывать расширения файлов; вернуть
  классическое контекстное меню (как в Windows 10) в Windows 11; скрыть
  подсказки для папок и значков рабочего стола; открывать проводник на
  «Этот компьютер» вместо «Быстрый доступ»/«Главная»; показывать «Снять
  задачу» прямо в контекстном меню панели задач.

Все эти настройки применяются и к аккаунту, созданному при установке, и ко
всем будущим аккаунтам на машине.

### Wi-Fi — *(экран Wifi)*

```json
"wifi": {
  "ssid": "MyNetwork",
  "authentication": "WPA2Personal",
  "password": "hunter2000",
  "connect_hidden": false,
  "raw_profile_xml": null
}
```

`wifi` целиком необязателен: опустите его (или оставьте `null`), чтобы не
настраивать Wi-Fi вообще.

- `authentication`: `"Open"`, `"WPA2Personal"` или `"WPA3Personal"`.
  `password` обязателен (≥8 символов), если `authentication` не `"Open"`.
- `raw_profile_xml`: если задан, этот сырой XML профиля WLAN (экспорт через
  `netsh wlan export profile key=clear`) используется как есть вместо
  построения профиля из `ssid`/`authentication`/`password`/`connect_hidden`;
  в этом случае четыре перечисленных поля становятся необязательными.

<a id="удаление-приложений-и-компонентов"></a>
### Удаление приложений, компонентов и необязательных компонентов — *(экран Apps)*

Три отдельных списка с тремя разными механизмами удаления. Они разделены,
потому что имя из одного списка недопустимо в другом.

```json
"remove_apps": ["OneDrive", "Terminal", "Store"],
"remove_features": ["InternetExplorer"],
"remove_optional_features": ["Recall"]
```

**`remove_apps`** (пакеты Appx, удаляются через
`Remove-AppxProvisionedPackage`), любое из:

`3DViewer`, `BingSearch`, `Calculator`, `Camera`, `Clipchamp`, `Clock`,
`Copilot`, `Cortana`, `DevHome`, `Family`, `FeedbackHub`, `GameAssist`,
`GetHelp`, `MailAndCalendar`, `Maps`, `MediaPlayerModern`, `MixedReality`,
`MoviesAndTV`, `News`, `Notepad`, `Office`, `OneDrive`, `OneNote`,
`Outlook`, `Paint`, `Paint3D`, `People`, `PhoneLink`, `PowerAutomate`,
`QuickAssist`, `Skype`, `SnippingTool`, `SolitaireCollection`,
`StickyNotes`, `Store`, `Teams`, `Terminal`, `Tips`, `ToDo`,
`VoiceRecorder`, `Wallet`, `Weather`, `XboxApps`.

`OneDrive` внутри обрабатывается иначе, чем остальные (он не распространяется
как пакет Appx: инструмент удаляет оставшийся ярлык и установочные
исполняемые файлы и убирает запись автозапуска), но использовать его нужно
так же: просто указать имя в этом же списке.

**`remove_features`** (необязательные *возможности* Windows, удаляются через
`Remove-WindowsCapability`), любое из: `InternetExplorer`, `WordPad`,
`PowerShellISE`, `OpenSSHClient`, `MediaPlayer`, `Speech`, `Handwriting`,
`WindowsHello`, `MathInputPanel`, `OneSync`, `StepsRecorder`.

**`remove_optional_features`** (устаревшие необязательные компоненты Windows,
удаляются через `Disable-WindowsOptionalFeature`, это третий отдельный
механизм), любое из: `Recall`, `MediaFeatures`, `RemoteDesktopClient`.

### Персонализация — *(экран Personalization)*

```json
"personalization": {
  "system_theme": "",
  "apps_theme": "",
  "accent_color": null,
  "show_accent_on_start_taskbar": false,
  "show_accent_on_title_bars": false,
  "disable_transparency": false,
  "solid_color_wallpaper": null
}
```

- `system_theme` / `apps_theme`: `"light"` или `"dark"`; пустое значение или
  отсутствие оставляет тему Windows по умолчанию.
- `accent_color` / `solid_color_wallpaper`: 6-значные шестнадцатеричные цвета
  (например, `"FF8800"`) без префикса `#`. `solid_color_wallpaper` заменяет
  фон рабочего стола однотонным цветом; обои из файла изображения не
  поддерживаются.
- Эти настройки применяются ко всем будущим аккаунтам, а не только к
  созданному при установке.

### Специальные возможности — *(экран Accessibility)*

```json
"sticky_keys": { "mode": "default", "flags": [] },
"lock_keys": null
```

- `sticky_keys.mode`: `"default"` (значение Windows по умолчанию: включено,
  5×Shift активирует), `"disabled"` (отключает сам ярлык 5×Shift, а не только
  визуальные дополнения) или `"custom"` (используйте `flags`, любое
  подмножество из `HotKeyActive`, `Indicator`, `TriState`, `TwoKeysOff`,
  `AudibleFeedback`, `HotKeySound`).
- `lock_keys`: `null` оставляет поведение Caps/Num/Scroll Lock нетронутым.
  Задайте объект, чтобы настроить все три:

  ```json
  "lock_keys": {
    "caps_lock":   { "initial": "off", "behavior": "toggle" },
    "num_lock":    { "initial": "on",  "behavior": "toggle" },
    "scroll_lock": { "initial": "off", "behavior": "ignore" }
  }
  ```

  `initial` — `"off"` или `"on"` (состояние сразу после запуска Windows);
  `behavior` — `"toggle"` (обычное) или `"ignore"` (нажатие клавиши вообще
  ничего не делает; вступает в силу после перезагрузки).

### Значки рабочего стола и папки «Пуска» — *(экран Desktop)*

```json
"desktop_icons": { "ThisPC": true, "RecycleBin": false },
"start_folders": ["Settings", "Documents", "Downloads"]
```

- `desktop_icons`: словарь; ключи, которые вы не указали, остаются по
  умолчанию, указанные задаются явно: `true` (показывать) или `false`
  (скрывать). Допустимые ключи: `ThisPC`, `UserFiles`, `Network`,
  `RecycleBin`, `ControlPanel`, `Desktop`, `Documents`, `Downloads`,
  `Music`, `Pictures`, `Videos`, `Gallery`, `Home`.
- `start_folders`: упорядоченный список специальных папок, закрепляемых
  рядом с кнопкой питания в меню «Пуск» Windows 11; порядок в списке — это
  порядок закрепления. Допустимые значения: `Settings`, `FileExplorer`,
  `Documents`, `Downloads`, `Music`, `Pictures`, `Videos`, `Network`,
  `PersonalFolder`. Пустой или отсутствующий список означает «оставить набор
  Windows по умолчанию»: выразить «закрепить ноль папок» этим полем
  невозможно.

Обе настройки применяются ко всем будущим аккаунтам, а не только к
созданному при установке.

### Визуальные эффекты — *(экран VisualEffects)*

```json
"visual_effects": { "mode": "default", "custom": {} }
```

- `mode`: `"default"` (без изменений), `"best_appearance"` (все эффекты
  включены), `"best_performance"` (все эффекты отключены) или `"custom"`
  (используется `custom`).
- `custom`: словарь «имя эффекта → `true`/`false`»; не указанные эффекты
  остаются по умолчанию. Допустимые ключи: `ControlAnimations`,
  `AnimateMinMax`, `TaskbarAnimations`, `DWMAeroPeekEnabled`,
  `MenuAnimation`, `TooltipAnimation`, `SelectionFade`,
  `DWMSaveThumbnailEnabled`, `CursorShadow`, `ListviewShadow`,
  `ThumbnailsOrIcon`, `ListviewAlphaSelect`, `DragFullWindows`,
  `ComboBoxAnimation`, `FontSmoothing`, `ListBoxSmoothScrolling`,
  `DropShadow`.

Применяется ко всем будущим аккаунтам, а не только к созданному при
установке.

### Меню «Пуск» и панель задач — *(экран Taskbar)*

```json
"taskbar_search": "",
"start_pins": { "mode": "default", "json": null },
"start_tiles": { "mode": "default", "xml": null },
"taskbar_icons": { "mode": "default", "xml": null }
```

- `taskbar_search`: `""`/отсутствует (по умолчанию Windows, поле поиска
  показано), `"hide"`, `"icon"` (только значок, без поля), `"box"` (явно, то
  же, что по умолчанию) или `"label"` (значок с текстовой подписью).
- `start_pins` (только Windows 11, в Windows 10 не действует): `mode` —
  `"default"`, `"empty"` (нет закреплённых приложений) или `"custom"`
  (требует `json`: сырой `{"pinnedList": [...]}` в формате, который ожидает
  политика Windows `ConfigureStartPins`).
- `start_tiles` (только Windows 10, в Windows 11 не действует): `mode` —
  `"default"`, `"empty"` (нет групп плиток) или `"custom"` (требует `xml`:
  сырой документ `LayoutModification.xml`).
- `taskbar_icons`: значки, закрепляемые на панели задач для всех будущих
  аккаунтов. `mode` — `"default"`, `"empty"` (нет закреплённых значков) или
  `"custom"` (требует `xml`: сырой `LayoutModification.xml` с
  `CustomTaskbarLayoutCollection`). Работает через заблокированную раскладку
  «Пуска», которая снимается при первом входе каждого аккаунта, поэтому
  потом пользователи могут менять панель задач сами; для этого в
  сгенерированный файл ответов также добавляется небольшая запланированная
  задача `UnlockStartLayout`. Для XML проверяется только корректность
  формата, но не схема раскладки панели задач Windows.

### Дополнительно — *(экран Advanced)*

```json
"install_vm_guest_tools": [],
"applocker_policy_xml": null,
"use_narrator": false,
"obscure_passwords": false
```

- `install_vm_guest_tools`: любое из `VBoxGuestAdditions`, `VMwareTools`,
  `VirtIoGuestTools`, `ParallelsTools`. Каждый запускает тихий установщик,
  который ищет ISO гостевых инструментов на дисках D–Z и просто пишет в лог,
  если образ не подключён. Если заранее не знаете гипервизор, можно
  безопасно перечислить все четыре «на всякий случай».
- `applocker_policy_xml`: сырой XML политики AppLocker. Проверяется только
  корректность XML, но не полная схема AppLocker: корректный по формату, но
  недопустимый XML политики проявится только как ошибка на целевой машине.
- `use_narrator`: автоматически запускает экранный диктор во время самой
  установки и при первом входе каждого будущего аккаунта.
- `obscure_passwords`: скрывает пароли аккаунтов в сгенерированном XML
  через Base64 вместо записи открытым текстом. Это **обфускация, а не
  шифрование**: соль — фиксированное публично документированное значение
  (соглашение Microsoft для unattend), поэтому оно лишь мешает найти пароли
  простым grep по файлу, и не более.

### Глобальный переключатель установки

```json
"hide_powershell_windows": false
```

При `true` каждое окно PowerShell, которое инструмент открывает во время
установки (встроенные твики и ваши собственные скрипты), работает скрытым, а
не видимым. На шаги на основе `cmd`/`reg`/`vbs` это не влияет, они в любом
случае не показывают окно.

<a id="пользовательские-скрипты"></a>
### Пользовательские скрипты — *(экран Scripts)*

```json
"system_scripts": [],
"default_user_scripts": [],
"first_logon_scripts": [],
"user_once_scripts": [],
"restart_explorer_after_scripts": false
```

Четыре категории, каждая — список объектов `{ "format": "...", "content":
"..." }`. `format` — одно из `cmd`, `ps1`, `reg`, `vbs` (`default_user_scripts`
не поддерживает `vbs`). Лимиты: `system_scripts` ≤4, `default_user_scripts`
≤3, `first_logon_scripts` ≤4, `user_once_scripts` ≤4.

- **`system_scripts`** — выполняются один раз в контексте системы, *до*
  появления любого пользовательского аккаунта.
- **`default_user_scripts`** — применяются к шаблону реестра пользователя
  по умолчанию, поэтому влияют на каждый аккаунт, созданный позже, включая
  ещё не существующие. Аккаунт, созданный при самой установке, затрагивается,
  только если он тоже создаётся по этому шаблону (обычно так и есть).
- **`first_logon_scripts`** — выполняются один раз, когда в систему впервые
  входит самый первый аккаунт.
- **`user_once_scripts`** — выполняются один раз *для каждого аккаунта*,
  включая будущие, при его первом входе.

`restart_explorer_after_scripts`: если выполнялись какие-либо
`first_logon_scripts`, после них перезапускает проводник (полезно, если
скрипт изменил то, что проводник кэширует).

<a id="значения-по-умолчанию"></a>
### Что даёт `profile init` (без пресета)

`schema_version: 1`, язык/локаль/раскладка — `"en-US"`,
`edition.mode: "interactive"`, аккаунтов нет, `first_logon.mode: "none"`,
`express_settings.mode: "interactive"`; всё остальное — нулевые значения JSON
(пустая строка/false/null/пустой список), то есть «спросить при установке»
или «оставить значение Windows по умолчанию» для каждой настройки, описанной
в этом руководстве.

## Встроенные пресеты

Два пресета вшиты в бинарник; используйте их через
`profile init <name> --preset <preset-name>`.

- **`minimal`** — по сути то же, что отсутствие пресета: интерактивный выбор
  редакции, без аккаунтов, интерактивные экспресс-настройки, явное `false`
  для трёх исходных системных твиков. Безопасная отправная точка, ничего
  лишнего не делает.
- **`single-user`** — один локальный администратор `admin` (пароль не задан,
  добавьте его перед реальным использованием), автовход в этот аккаунт
  (`first_logon.mode: "first_created_account"`) и
  `express_settings.mode: "all_disabled"` (вопросы про телеметрию и
  диагностику пропускаются полностью). Разумная отправная точка для личной
  машины, на которой вы единственный пользователь.

Оба пресета появились раньше нескольких полей, описанных выше (они написаны
под более раннюю, меньшую схему): всё, что в них не указано, получает
нулевое значение схемы, как и любое незаданное поле.

## Примеры профилей

## Проверка сгенерированного файла ответов

`validate`/`generate` проверяют только JSON-профиль по схеме. Они не могут
подтвердить, что Windows Setup примет получившийся XML от начала до конца,
потому что для этого нужен реальный запуск Windows Setup. Замены нет:
запишите результат на USB-флешку (или подключите в виртуальной машине) и
посмотрите, как проходит установка. Если в XML что-то не так, Windows Setup
обычно сообщает, какой элемент, в собственном диалоге ошибки или в
`setupact.log`/`setuperr.log` в `C:\Windows\Panther` (или в
`X:\Windows\Panther`, пока ещё работает среда PE).

## Проблемы и известные ограничения

- **Разметка диска намеренно не поддерживается.** Windows Setup всегда
  остановится и спросит, на какой диск или раздел устанавливать систему.
  Инструмент настраивает всё остальное вокруг этого интерактивного шага.
- **`bypass_online_account_requirement` работает по принципу best-effort.**
  Microsoft не раз меняла, как это работает; если обход перестанет
  работать на будущей сборке Windows, это изменение на стороне Microsoft, а
  не ошибка инструмента (хотя issue об этом всё равно приветствуется).
- **Файлы ответов для нескольких архитектур не поддерживаются.** Выбирайте
  один `processor_architecture` на профиль.
- **Можно настроить только один язык и одну раскладку клавиатуры** на
  профиль; дополнительные языки и раскладки не поддерживаются.
- **«Аварийного выхода» в виде сырого XML для произвольных компонентов
  unattend нет.** Если нужен компонент, для которого у инструмента нет поля,
  придётся вручную править сгенерированный `autounattend.xml`.
- **Обои из файла изображения не поддерживаются:** доступен только
  однотонный цвет (`personalization.solid_color_wallpaper`).
- **Изображение экрана блокировки не поддерживается:** механизм Microsoft для
  него доступен только в редакциях Enterprise/Education/Pro-SharedPC, что
  ненадёжно для аудитории инструмента (в основном Home/Pro), поэтому его
  оставили за бортом, а не выпустили в полурабочем виде.
